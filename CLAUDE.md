# Bount-CDP-Delivery

## Personal professional sandbox — never surface it anywhere
This repo (and every `cit-bank*` and `Bount-CDP*` repo) is **my own professional sandbox on my
own account**. It is not a team-shared repo, not a Bounteous-sponsored or Bounteous-approved
GitHub account, and not visible to CIT. It exists to keep my own organization, practice, and
proof-of-concept material, and to give the CIT work version control and a durable source of
truth, because there is a lot to keep up with and Confluence cannot hold all of it. It stays
invisible until the organizations sponsor something shared. **This is a standing rule, not a
preference. Do not ask whether to mention it; do not mention it.**

**1. External and client-facing artifacts.** Never mention, link to, cite, or imply the existence
of this repo, GitHub, or any file, path, commit, branch, or pull request in it — in Jira
comments or descriptions, Confluence, email, Slack, meeting decks, shared workbooks, attachments,
or anything else that leaves this repo. That includes "see the notes", "recorded in the
repo", GitHub URLs, and file paths. When an artifact needs supporting detail that lives here,
inline the content or omit the citation. Never point outward to this repo as a source.

**2. Conversation with me.** Do not volunteer or mention this repo or GitHub in replies or
summaries: no file names, paths, commit or branch names, pull request links or numbers,
"I committed", "I opened a PR", or "recorded in the repo" lines. Do the work, then report the
project outcome in plain terms. Mention the repo only if I ask about it first.

**3. Working inside it is unchanged.** Keep saving working material here as the durable archive.
This rule governs what is said and shown, not what is saved.

**4. Changing this rule.** Only I can lift it, and only by saying the organizations have
sponsored a shared repo.

## Other working rules (apply across my CIT work)
- Never post a comment (Jira, Confluence, GitHub, or any other system) on my behalf without my
  explicit approval. For Jira comments, only the literal phrase "Save this comment in Jira"
  authorizes a post or an edit.
- Do not commit credentials, tokens, API keys, signed contracts, or customer data.
- Names: real people's names are fine in this repo and in Jira. They never go into Confluence
  or any client-facing deliverable; use roles there.
